# 개인화 레이어 — 1층과 2층 사이의 오버라이드

**위치가 곧 설계다**: 개인화는 온톨로지(1층)를 고치지 않고, 빌드플랜(2층)이 1층을 조회할 때
**개인 프로파일의 오버라이드를 얹어 읽는다**. 공통 지식은 그대로, 적용만 개인화된다.

- 단위: **개인**(기관 아님 — 확정 사항). 프로파일 1인 1파일: `profiles/<이름>.json`
- 역할: 크라우드 피드백에서 공통 온톨로지를 보호하는 **격리막의 수용 장치**.
  원장(ledger) 판정이 "개인화"면 여기로 등재된다 — 공통 승격은 검증 통과분만.

## 파일

- `profiles/<이름>.json` — 개인 프로파일(오버라이드 + 성향)
- `resolve.py` — 유효 온톨로지 조회기: 1층 + 개인 오버라이드 병합, **출처 표시** 필수

## 프로파일 스키마

```json
{
  "user": "이름",
  "overrides": [
    { "path": "entities.요약박스.문체.길이", "value": "…",
      "근거": "FB-XXX 개인화 판정('26. M. D.)", "원문": "사용자가 실제로 한 말" }
  ],
  "성향": {
    "byline_기본부서": "AI혁신처",
    "표_스타일_선호": "샌드위치",
    "강조_수위": "절제(accent 1회 선호)"
  }
}
```

- **overrides** — 1층 규칙 값을 점 경로로 덮어쓴다. 반드시 근거(원장 FB ID)와 원문을 남긴다.
- **성향** — 규칙이 아닌 기본값 선호(2·3층 재량이 참조). 자유 키.

## 적용 지점

1. **2층 빌드플랜**: 온톨로지 조회 시 `resolve.py`로 읽으면 오버라이드가 반영되고,
   반영된 값에는 `[개인화]` 출처가 붙는다 — 승인 화면에서 사용자가 자기 취향이 적용됐음을 안다.
2. **3층 생성**: 성향(선호 표 스타일·강조 수위·기본 부서명)을 재량 판단의 기본값으로 참조.
3. **게이트**: 게이트 기준은 개인화 대상이 아니다 — 1쪽·어절분리·문체 하드 규칙은 공통 불변.
   (개인화는 "취향의 여지가 있는 값"에만 허용. 하드 게이트를 오버라이드하는 항목은 등재 거부.)

## 격리막 → 개인화 등재 절차

1. 원장(ledger) 판정에서 범위="개인" 확정(README의 격리막 3질문).
2. 해당 항목을 프로파일 overrides/성향에 기록, 원장 처리 필드에 "profiles/<이름>.json 등재" 기입.
3. 이후 같은 취향이 **다른 사용자들에게서도 반복 관찰**되면(관측 로그·원장), 검증 절차를 거쳐
   공통 승격 후보로 재상정한다 — 개인화는 공통 승격의 대기실이기도 하다.

## 조회 사용법

```bash
python3 personalization/resolve.py <프로파일> [점.경로]
# 예: python3 personalization/resolve.py default entities.요약박스.문체
#     → 병합 결과 + 오버라이드된 값에 [개인화] 표시
```
