# 문서지능 | Artifact Intelligence

## 내용은 머릿속에 다 있는데, 보고서로 앉히는 데 반나절이 갑니다

**무엇을·누구에게·왜 보고할지와 사실·수치만 넘기면, 결재에 올릴 수 있는 보고서 초안이 나옵니다.**
목차 잡기·개조식 변환·한 장 맞춤·한글(HWPX) 변환은 규칙이 알아서 합니다. 사람은 맞는지 보고 고칠 데만 짚습니다.

## 이런 분께 좋습니다

보고서에 담을 내용은 이미 아는데, 그걸 결재 올라갈 문서로 만드는 데서 시간이 새는 분들을 위해 만들었습니다.

- **보고서를 자주 쓰는 실무자** — 무엇을 담을지는 아는데 형식 맞추는 데 반나절이 가던 분.
- **개조식이 아직 손에 안 익은 분** — 서술식으로 적어도 개조식 명사형으로 다듬어 냅니다.
- **한 장에 자꾸 넘치는 분** — 1페이지 보고서를 실제로 한 쪽에 맞춥니다. 넘치면 무엇을 줄일지 짚어 드립니다.
- **최종본이 한글(HWP)로 나와야 하는 분** — 화면에서 확인한 그대로 HWPX로 옮겨 드립니다.
- **AI로 초안은 뽑는데 결재 품질이 안 나오는 분** — 서술식 문장·한 장 초과·없는 수치 지어내기를 규칙이 막습니다.

현황보고·검토보고·결과보고·추진계획·시행문·발표 슬라이드까지, 결재판에 올라가는 문서에 바로 씁니다.

---

## 이렇게 씁니다 (3단계)

**1. 의도와 자료를 넘깁니다.** 평범한 말로 됩니다.
　예: *"상반기 청년일자리 사업 결과, 국장님께 결과보고로. 자료는 여기 있습니다…"*

**2. 구성안을 먼저 봅니다.** 어떤 유형으로 보고, 목차를 어떻게 잡을지 초안을 짓기 전에 보여 드립니다. 승인하면 그제서야 씁니다.

**3. 초안을 받습니다.** 개조식으로 다듬고 한 장에 맞춘 HTML·PDF·HWPX가 나옵니다. 고칠 데는 편집 화면에서 짚으면 그 자리에서 반영됩니다.

> 백지를 채우는 방식이 아닙니다. 규칙이 거의 완성된 초안을 짓고, 사람은 판단만 합니다.

---

## 서술식으로 적으면, 개조식으로 나옵니다

같은 내용도 결재판에서는 30초 안에 읽혀야 합니다. 문서지능은 뭉친 문장을 끊어 핵심부터 세웁니다.

**넣은 문장** (66자, 정보 세 개가 한 문장에)
> 올해 상반기 청년일자리 사업은 목표 200명 대비 173명을 채용하여 목표의 86.5%를 달성하였으며, 배정 예산 12억 원 중 10억 4천만 원을 집행하였고, 참여자 만족도 조사에서는 5점 만점에 4.2점을 기록하였습니다.

**나온 개조식**

```
□ 상반기 청년일자리 사업 — 목표 대비 86.5% 달성
　○ 채용: 173명 (목표 200명)
　○ 예산 집행: 10.4억 원 (배정 12억 원)
　○ 참여자 만족도: 4.2점 / 5점
```

날짜 표기, 감소 수치 강조, 붙임 규범까지 규칙대로 맞춰 냅니다.

## 무엇이 다른가

- **규칙이 형식을 정합니다.** 실물 보고서 1만 6천여 건에서 뽑은 목차·문체·디자인 규칙이 기준입니다. 모델이 매번 다르게 쓰지 않습니다.
- **통과 못 하면 안 나갑니다.** 서술식 종결, 한 장 초과, 자료에 없는 수치·이름을 세 겹 검사가 막습니다. 걸리면 스스로 고쳐 다시 냅니다.
- **잘못 짚었으면 되돌립니다.** "이건 검토보고가 아니라 결과보고였네" 싶으면 구성 단계로 되돌아갑니다.
- **낸 문서를 다시 넣으면 이어서 고칩니다.** 완성한 HTML을 다시 넣으면 편집을 그대로 잇습니다.
- **없는 그림은 안 만듭니다.** 올린 첨부에서 필요한 부분을 잘라 넣고, 적합한 게 없어 AI 삽화를 만들면 'AI 생성물' 표기를 붙입니다.

## 한 장으로 보는 구조

```
의도 + 자료
   │
   ▼  유형 판별            자료에서 장르와 보고 목적을 규칙으로 가릅니다
   ▼  구성안 설계          유형별 목차·개체 방법론으로 짜고, 사용자가 승인합니다
   ▼  초안 생성            규칙이 담긴 완성 프롬프트로 3층 인스턴스를 채웁니다
   ▼  문체·조판·사실 검증   개조식·한 장·원문 대조 세 관문을 넘어야 나갑니다
   ▼  조판·조립 → HTML      장르별 조립기가 디자인 정본대로 굽습니다
   └▶ 내보내기             json · md · html · pdf · hwpx
```

문서 제작을 네 층으로 나눕니다.

| 층 | 우리 것 | 확정하는 것 |
|---|---|---|
| 1층 규칙 | **온톨로지** (하나) | 개체가 무엇이고 어떤 방법론을 갖는가 |
| 2층 설계 | **빌드플랜** | 유형 + 개체 목록 + 개체별 방법론 |
| 3층 인스턴스 | **인스턴스 JSON** | 자료를 방법론에 넣어 나온 실제 구성 |
| 4층 결과 | **HTML / PDF / HWPX** | 최종 산출물 |

규격은 CSS와 조립기에 결정론적으로 고정돼 있습니다. 같은 콘텐츠는 어느 런타임에서든 폰트까지 픽셀 단위로 같게 나옵니다.

## 세 표면, 하나의 규칙

세 가지 방식으로 같은 파이프라인을 씁니다. 규칙과 무거운 처리는 정책 서버에서 돌고 어느 표면이든 결과만 받아 가므로, 규칙이 갈라지지 않습니다.

| 표면 | 무엇 | 쓰는 법 |
|---|---|---|
| **웹앱** | 브라우저에서 바로, 설치 없이 | https://artifact-intelligence.app |
| **스킬** | Claude Code 플러그인 | [`SKILL.md`](SKILL.md) · 아래 설치 |
| **MCP** | Codex 등 에이전트가 도구로 호출 | `mcp/server.py` ([`mcp/README.md`](mcp/README.md)) |

산출 장르는 다섯입니다 — 1페이지 보고서 · 풀버전 보고서 · 시행문 · 규정 · 보도자료.

## 규칙은 공개하지 않습니다

판별 규칙·문체 정본·목차 논리는 정책 서버(artifact-intelligence.app)에만 둡니다. 설치본이 받는 것은 판정 결과와 그 문서용 작성 지침뿐입니다. 조립·검사·조판·한글 변환 같은 무거운 처리도 서버가 하므로, 규칙은 설치한 컴퓨터에 오지 않습니다.

## 설치

**Claude Code** — 마켓플레이스로:
```
/plugin marketplace add Kminer2053/Artifact-Intelligence-public
/plugin install artifact-intelligence@artifact-intelligence
```

**Codex** — 스킬 폴더를 받은 뒤 MCP로 붙입니다:
```bash
codex mcp add artifact-intelligence -- "$(pwd)/mcp/run.sh"
```

**웹앱** — 설치 없이 https://artifact-intelligence.app 에서 바로 씁니다.

설치하면 첫 기동 때 정책 토큰을 자동으로 받아 서버에 연결합니다. 파이썬 3.10 이상이 필요합니다.

### 필요한 것

- 파이썬 3.10 이상 (첫 기동 때 MCP 도구 의존성을 자동으로 한 번 설치합니다)
- 인터넷 — 규칙과 처리는 정책 서버에서 돕니다

무거운 처리(HWPX 변환·조판 검증·업로드 파싱·AI 이미지 생성)는 전부 서버가 합니다. 그래서 설치한 컴퓨터에 크롬·poppler·Node 같은 것을 따로 갖출 필요가 없습니다.
