# 보고목적 유형 → 표준 목차 레퍼런스

> 용도: 1p 보고서 생성 스킬이 "사용자 의도 파악 → 보고유형 판별 → 목차 확정" 단계에서 직접 참조한다.
> 출처: `research/ontology/extracted/07_repo-1p구성.md`(R구-01~53, 이하 R구-XX로 인용). 물리 스켈레톤은 □ 대제목 슬롯이 **4개 고정**이다(R구-03) — 이 문서의 "표준 4대제목"은 그 4슬롯에 맞춘 기본형이며, 콘텐츠가 적으면 3개(압축, 4번 슬롯 비움), 논리 주제가 5개로 늘면 인접 2개를 한 슬롯에 합쳐 4개를 유지한다(R구-24). 5개 대제목이 병합 없이는 안 줄어들면 풀버전 전환을 검토한다(R구-32, R구-48).

## 1. 유형 판별 결정 규칙 — 5범주 → 12유형

판별 축은 하나뿐이다: **"보고받는 사람이 이 문서를 받고 나서 무엇을 해야 하는가"** (R구-01).

| 5범주(할 일) | 해당 12유형 |
|---|---|
| 알면 됨 | ① 현황·동향 보고 |
| 판단·선택해야 함 | ② 검토·의사결정 / ④ 문제해결·개선방안 / ⑦ 회의안건 / ⑩ 제휴협력검토 |
| 실행 승인이 필요함 | ③ 사업·정책계획 / ⑨ 행사계획 / ⑪ 예산·구매·품의 |
| 완료 사실·성과 확인 | ⑥ 결과·성과 보고 |
| 후속조치가 필요함 | ⑤ 이슈·리스크·사고 / ⑧ 회의결과 / ⑫ 의견조회·협조요청 |

원문 §1표는 5범주마다 대표 유형 1개만 명시한다(①③⑥ 세 유형만 [명시규칙]). ②를 제외한 판단·선택 계열 3유형과 실행승인·후속조치 계열 나머지 유형은 목적 서술로 재분류한 것으로 확정 규칙이 아니다[해석] — 한 범주에 유형이 여럿이면 §3의 소재 신호로 최종 확정한다.

## 2. 12유형별 표준 목차

### ① 현황·동향 보고 — 알면 됨 (R구-07)
- **판별 신호**: "현황/동향/추이/트렌드/모니터링", 정기·주간·월간 보고, 시장·언론 동향 공유. 결정 요청 문구 없이 정보 전달만 하는 경우.
- **표준 4대제목**
  1. 보고배경 — 왜 이 업무·보고가 있는가? 사업 개요와 이번 보고의 계기. (구 '보고요지'는 요약박스와 중복이라 폐기 — 실무자 검수 '26. 7. 25.)
  2. 주요현황·동향 — 지금 수치·사실은 무엇이며, 외부환경·이해관계자·시장 흐름은 어떠한가?
  3. 영향·시사점 — 우리 기관 업무에 어떤 영향을 주는가?
  4. 향후관리 — 무엇을 모니터링하며 언제 다시 보고하는가?
- **압축형(3, 마지막 슬롯 비움)**: 주요현황 → 시사점 → 향후관리
- **표**: 권장(수치·비교 데이터가 있으면 1개, R구-39)

### ② 검토·의사결정 보고 — 판단·선택 (R구-08)
- **판별 신호**: "검토/검토 부탁/의견 주세요/~여부 검토/가부 판단", 이미 존재하는 대안·선택지 중 상급자가 고르는 구조.
- **표준 4대제목** (실무자 검수 '26. 7. 25. 개정 — 구 '검토결과 선행+결정요청'은 폐기)
  1. 검토배경 — 왜 검토가 필요하며, 법령·예산·이해관계·리스크상 쟁점은 무엇인가?
  2. 대안검토 — 대안별 장단점·비용·효과는 어떻게 비교되는가?
  3. 검토의견 — 실무 부서의 권고 의견과 그 근거. **의견으로 제시하되 결정을 채근하지 않는다.**
  4. 향후계획 — 결정 이후 일정. 결정 기한·기대효과를 일정으로 간접 전달. (효과 중심 마무리가 자연스러우면 '기대효과'로 대체 가능)
- **압축형(3)**: 검토배경 → 대안검토 → 검토의견
- **표**: 권장(대안 비교표)
- 상대가 외부기관·기업이면 ⑩으로, 원인 규명부터 필요하면 ④로 재판별(§3).

### ③ 사업·정책계획 보고 — 실행 승인 (R구-09)
- **판별 신호**: "추진계획/시행계획/~사업 계획(안)/신규 사업/제도 도입/프로젝트 착수/추진 방안". 새 사업·제도를 시작하기 위한 승인 요청.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '추진방향' 선행 폐기)
  1. 추진배경 — 왜 필요한가? 정책환경·기관전략·문제 상황.
  2. 주요내용 — 무엇을 하는가? 과업 범위·대상·핵심 목표·세부내용.
  3. 추진체계 — 일정·예산·역할분담·협업체계는 어떠한가?
  4. 향후계획 — 세부 일정과 보고·결재·협조 사항은 무엇인가?
- **압축형(3)**: 추진배경 → 주요내용 → 향후계획
- **표**: 선택(추진체계 일정표)
- 1회성 이벤트가 핵심이면 ⑨로, 예산·구매가 핵심이면 ⑪로 재판별(§3).

### ④ 문제해결·개선방안 보고 — 판단·선택 [해석] (R구-10)
- **판별 신호**: "문제/애로사항/개선방안/개선안/프로세스 개선/제도 개선/~해결 방안". 대안 선택이 아니라 원인 규명부터 필요한 경우.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '개선방향' 선행 폐기)
  1. 현황·문제점 — 문제가 어떤 규모·양상으로 나타나는가? 수치·민원·현장 사실.
  2. 원인분석 — 제도·프로세스·인력·시스템상 원인은 무엇인가?
  3. 개선방안 — 단기·중기·장기(또는 내부·외부) 개선안은 무엇인가?
  4. 실행계획 — 담당·일정·비용·기대효과는 어떠한가?
- **압축형(3)**: 문제점 → 개선방안 → 실행계획
- **표**: 선택

### ⑤ 이슈·리스크·사고 보고 — 후속조치 (R구-11)
- **판별 신호**: "사고/이슈/민원/긴급/속보/리스크/돌발/언론보도 대응/경위". 부정적·돌발 사건, 신속 대응이 필요한 경우.
- **표준 4대제목**
  1. 상황요약 — 발생 사실·현재 상태와 피해 규모(민원·데이터·재무). 피해상황을 이 절에 포함.
  2. 발생원인 — 원인은 무엇이고 시간순 경과는 어떠했는가?
  3. 조치내역 — 이미 취한 조치와 진행 중인 조치는 무엇인가?
  4. 향후대응 — 추가 조치·보고라인·재발방지 대책은 무엇인가?
  (절 명칭 실무자 검수 '26. 7. 25. — 구 '발생경위·영향분석/조치현황'에서 조정)
- **압축형(3)**: 상황요약 → 조치내역 → 향후대응
- **표**: 비권장(속도 우선, 서술 위주)
- 회의 중 논의된 사고라도 "돌발 사건" 자체가 핵심이면 ⑧보다 이 유형이 우선(§3).

### ⑥ 결과·성과 보고 — 완료 사실·성과 확인 (R구-12)
- **판별 신호**: "결과보고/성과보고/완료보고/종료보고/실적/정산/~완료 결과". 이미 끝난 사업·행사·업무의 사실 확인.
- **표준 4대제목** (실무자 검수 '26. 7. 25. 개정 — 구 '결과요약' 선행은 요약박스와 중복이라 폐기)
  1. 추진배경 — 왜 추진했는가? 목표·계기·상위 방침.
  2. 추진내용 — 무엇을 어떻게 했는가? 기간·대상·조치 내역.
  3. 추진결과 — 계획 대비 결과·정량 성과와 미흡한 점. (구 '문제점·시사점'은 여기와 향후계획에 흡수)
  4. 향후계획 — 후속 조치·개선·다음 일정.
- **압축형(3)**: 추진내용 → 추진결과 → 향후계획
- **표**: 권장(정량 성과표)
- 소재가 "회의" 자체의 완료 보고라면 ⑧(회의결과)로, 사업·행사·업무 전반의 완료 보고는 이 유형으로 판별한다(§3).

### ⑦ 회의안건 보고 — 판단·선택 [해석] (R구-13)
- **판별 신호**: "회의 안건/안건 상정/사전 자료/~회의 자료". 회의 개최 **이전**, 참석자가 논의·판단하도록 배포하는 자료.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '안건요지' 선행 폐기)
  1. 논의배경 — 안건이 상정된 이유·경과·현황은 무엇인가?
  2. 안건 주요내용 — 회의 일시와 안건의 핵심 내용·상정 목적은 무엇인가?
  3. 주요쟁점 — 선택지·이견·검토가 필요한 사항은 무엇인가?
  4. 논의사항 — 회의에서 논의·확정할 항목은 무엇인가?
- **압축형(3)**: 논의배경 → 주요쟁점 → 논의사항
- **표**: 비권장

### ⑧ 회의결과 보고 — 후속조치 (R구-14)
- **판별 신호**: "회의결과/회의록/논의결과/회의 후속". 회의 개최 **이후**, 기록·후속조치 목적.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '결과요약' 선행 폐기)
  1. 회의개요 — 일시·장소·참석자·안건은 무엇인가?
  2. 주요논의 — 안건별 논의 요지와 이견은 무엇인가?
  3. 결정사항 — 확정된 내용과 이견 여부는 무엇인가?
  4. 조치계획 — 담당자·기한·후속보고는 어떻게 되는가?
- **압축형(3)**: 회의개요 → 결정사항 → 조치계획
- **표**: 선택(결정사항 표)
- ⑦과의 판별은 시제 하나로 충분: 개최 전=⑦, 개최 후=⑧(§3).

### ⑨ 행사계획 보고 — 실행 승인 [해석] (R구-15)
- **판별 신호**: "행사/세미나/포럼/워크숍/행사 준비/개최 계획". 1회성 이벤트 개최 전 준비·승인.
- **표준 4대제목**
  1. 행사개요 — 행사명·일시·장소·참석자는 무엇인가?
  2. 추진배경·주요내용 — 개최 목적·필요성·기대효과는 무엇이고, 프로그램·진행순서·메시지는 무엇인가?
  3. 준비사항 — 홍보·의전·안전·역할분담은 어떠한가?
  4. 협조사항 — 타 부서·기관 협조 요청은 **명확·직접적으로**. 승인·결정 필요사항(예산·참석 일정)은 이 절에서 채근하지 않고 요약박스(~요청드림)와 향후 일정으로 간접 표현. ('결정' 용어는 채근 느낌으로 상대에게 부담 — 실무자 판정 '26. 7. 26., 구 '협조·결정사항'에서 개정)
- **압축형(3)**: 행사개요 → 주요내용 → 준비사항 (협조·승인 사항이 남아 있으면 4대제목형을 우선 사용)
- **표**: 선택(프로그램·일정표)

### ⑩ 제휴·협력 검토 보고 — 판단·선택 [해석] (R구-16)
- **판별 신호**: "제휴/협력/MOU/파트너십/협업 검토/공동사업". 외부기관·민간기업·지자체와의 협력 여부 판단.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '검토결과' 선행 폐기)
  1. 제휴배경 — 협력 필요성·상대기관 개요·제안 경과는 무엇인가?
  2. 협력내용 — 역할분담·사업모델·범위·비용은 무엇인가?
  3. 기대효과·리스크 — 수익·이미지 효과와 법무·운영 리스크는 무엇인가?
  4. 검토의견·향후계획 — 실무 부서의 검토 의견과 그 근거, 결정 이후 협약·협의 일정.
- **압축형(3)**: 제휴배경 → 협력내용 → 검토의견·향후계획
- **표**: 선택(비교표)

### ⑪ 예산·구매·품의 보고 — 실행 승인 [해석] (R구-17)
- **판별 신호**: "예산/품의/구매/지출/계약/집행 승인/견적". 금액이 명시된 승인 요청.
- **표준 4대제목** (A/B 실물 판정 '26. 7. 25. 개정 — 구 '요청사항' 선행 폐기, 요청은 요약박스가 담당)
  1. 추진배경 — 왜 필요한가? 문제 상황·기존 예산 여부·상위 방침.
  2. 산출근거 — 단가·수량·비교견적·예산과목은 무엇인가?
  3. 추진방법·소요예산 — 계약방식·일정·소요액. 승인 요청의 실질은 "승인 즉시 ~ 착수" 일정으로 간접 전달.
  4. 기대효과 — 업무개선·비용절감·리스크감소 효과는 무엇인가?
- **압축형(3)**: 추진배경 → 산출근거 → 추진방법·소요예산
- **표**: 권장(단가·수량·견적 비교표 — 사실상 필수급)

### ⑫ 의견조회·협조요청 — 후속조치 [신설] (FB-020, '26. 7. 26.)
- **판별 신호**: "의견조회/의견 회신/확인 요청/협조 요청/검토 후 회신". 수신이 상급자가 아니라 관련 부서·기관(수평)이고, 첨부·대상물을 확인해 의견을 제출하게 하는 것이 목적.
- **표준 4대제목**
  1. 검토 배경 — 왜 이 조회가 필요한가? 대상물의 성격과 확인이 필요한 이유.
  2. 검토 대상 — 무엇을 확인해달라는 것인가? 범위·구성·참고 표시.
  3. 검토 방법·요청사항 — 어떻게 확인하고 의견을 내나? **협조 요청은 명확·직접적으로.**
  4. 회신 기한·활용 — 언제까지·어디로 회신하며, 의견은 어디에 반영되는가?
- **압축형(3)**: 검토 대상 → 검토 방법·요청사항 → 회신 기한·활용
- **표**: 선택(확인 대상 목록이 많으면 목록표)
- 요청의 실질은 요약박스(~요청드림)가 담당. 상급자 결정을 구하면 ②로, 행사 부속 협조면 ⑨로 재판별.
- 선례: 의견조회 표본 1건(유형 신설의 검증 재료)

## 3. 유형 확정이 애매할 때 우선순위 규칙

1. **사용자 명시 최우선.** 사용자가 보고유형·목차를 이미 지정했다면 판별 절차를 생략하고 그대로 따른다(R구-42 원칙의 유형 판별 확장 적용).
2. **시제가 소재보다 우선한다.** 같은 소재(회의·사업·행사)라도 "아직 발생 전"과 "이미 발생·완료"는 완전히 다른 유형이다.
   - 회의: 개최 전 → ⑦ 회의안건 / 개최 후 → ⑧ 회의결과
   - 사업·행사: 착수 전 승인요청 → ③ 사업·정책계획 또는 ⑨ 행사계획 / 종료 후 결과 → ⑥ 결과·성과
3. **소재가 특정 카테고리에 강하게 결부되면 범주 내 다른 유형보다 우선한다.**
   - 금액·계약·구매가 핵심 → ⑪ 예산·구매·품의 (③보다 우선)
   - 외부기관·기업과의 협력이 핵심 → ⑩ 제휴협력검토 (②보다 우선)
   - 1회성 행사·이벤트가 핵심 → ⑨ 행사계획 (③보다 우선)
   - 돌발·부정적 사건(사고·민원·언론)이 핵심 → ⑤ 이슈·리스크·사고 (①보다 우선, ⑧보다도 우선)
4. **위 신호가 전혀 없고 5범주만 뚜렷하면 범주의 기본형으로 수렴한다.**
   - 판단·선택 기본형 = ② 검토·의사결정
   - 실행승인 기본형 = ③ 사업·정책계획
   - 후속조치 기본형 = ⑧ 회의결과(회의 소재가 없으면 ⑤ 이슈·리스크·사고)
5. **그래도 애매하면 추측으로 확정하지 않고 사용자에게 직접 확인한다** — "이 문서를 받는 사람이 읽고 나서 무엇을 해야 하나요?"(R구-46·R구-52의 인간 확인 원칙 적용).
