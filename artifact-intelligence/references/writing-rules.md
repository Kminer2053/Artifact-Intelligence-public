# 문체 규칙 — 공문서·개조식 (1p 보고서)

콘텐츠를 **생성하는 시점에** 적용하는 규칙이다. 초안을 쓴 뒤 고치는 교정 체크리스트가 아니라, 처음 쓸 때부터 이 형태로 쓴다. 전부 ❌→⭕ 대조쌍으로 판정 가능하게 구성했다.

> **기계 판정**: 이 규칙들은 `build/stylelint.py`가 자동 판정한다(hard 위반 = 게이트 실패, `render_verify.sh`에 편입). 린터 자체는 `test/style-golden.json` 골든 테스트로 검증된다 — 이 파일의 대조쌍을 고치면 골든 케이스도 함께 갱신할 것. 정본은 온톨로지 `writing_profiles.gongmun-gaejosik`.

## 1. 개조식 명사형 종결 규칙

### 1-1. 서술식 종결 금지

□○-* 위계의 모든 항목은 명사형으로 끝낸다. 하십시오체·해요체로 문장을 완결하지 않는다.

| ❌ 서술식 | ⭕ 개조식 |
|---|---|
| 신규 지침을 마련하였습니다 | 신규 지침 마련 |
| 예산을 조기에 집행하겠습니다 | 예산 조기 집행 추진 |
| 문제가 발생한 것으로 확인됩니다 | 문제 발생 확인 |
| 다음 달부터 시행할 계획입니다 | 다음 달부터 시행 예정 |
| 집행률이 개선될 것으로 보입니다 | 집행률 개선 전망 |

### 1-2. 종결 어휘 치환표

서술형 어미를 아래 명사형 종결어로 바로 바꿔 쓴다. 이 표가 사실상 개조식 어휘장이다.

| 서술식 어미(❌) | 개조식 종결(⭕) | 비고 |
|---|---|---|
| ~할 것으로 예상됩니다/보입니다 | ~예상 | 추측·전망 |
| ~할 것으로 전망됩니다 | ~전망 | 추측·전망(중장기) |
| ~을 완료하였습니다 | ~완료 | 종료된 사실 |
| ~이 필요합니다 | ~필요 | 판단·요청 |
| ~을 추진하겠습니다/추진할 계획입니다 | ~추진 | 진행 의지 |
| ~을 검토하고 있습니다 | ~검토 중 / ~검토 | 진행 중 |
| ~을 시행합니다/시행하고자 합니다 | ~시행 | 확정된 조치 |
| ~로 확인되었습니다 | ~확인 | 사실 확정 |
| ~을 강화하겠습니다 | ~강화 | 조치 방향 |
| ~으로 판단됩니다 | ~판단 | 평가 |
| ~할 예정이었으나 이를 유예하였습니다 | ~예정 → 유예 | 경과+결과 압축 |
| ~하기로 하였습니다 | ~함 | 결정 사실(부득이 서술형 필요 시 최소형) |

### 1-3. 예외 — 요약박스만 다름

□○-* 본문 항목은 예외 없이 명사형 종결이다. **요약박스만** `~보고드림`으로 서술형 종결한다(두괄식 문단이라 별도 규칙 적용, §4 참조). 본문에 하십시오체가 섞이면 장르 규범 위반이다.

## 2. ○ 항목 45자 이내 — 압축 어휘 치환 사전

### 2-1. 조사구·표현 치환표

| 장황한 표현(❌) | 압축(⭕) | 처리 방식 |
|---|---|---|
| ~에 대해 / ~에 대한 / ~에 대하여 | *(삭제, 명사에 조사 직결)* | "예산에 대해 검토" → "예산 검토" |
| ~을 통해 / ~을 통한 | ~로 / ~으로 | "협의를 통해 결정" → "협의로 결정" |
| ~와 관련된 / ~와 관련하여 | ~ 관련 | "항로와 관련된 이슈" → "항로 관련 이슈" |
| ~할 수 있다 | *(단정형으로 바꾸거나 삭제)* | 가능성 서술 대신 사실을 단언 — "개선할 수 있다" → "개선함" |
| ~것으로 예상된다/확인된다 | ~예상 / ~확인 | §1-2와 동일 |
| ~하는 것이 필요하다/중요하다 | ~필요 | "검토하는 것이 필요합니다" → "검토 필요" |
| 이중피동(보여지다, 되어지다, 여겨지다) | 단일피동(보이다, 되다, 여기다) | 피동 접사 중복 제거 |
| 명사+적 (강조 불필요 시) | 적 삭제 | "행정적 절차" → "행정 절차" (단, "전략적 대응"처럼 강조가 필요하면 유지) |
| A**의** B**의** C (의 2회 이상) | A B C 또는 동사형 | "업무의 효율성의 개선" → "업무 효율 개선" |
| 여러/많은/각/모든 + 명사 + **들** | 들 삭제 | "여러 부서들" → "여러 부서" (수식어 없이 단독으로 복수를 표시할 때는 유지) |

### 2-2. 압축 우선순위

한 항목이 45자를 넘으면 아래 순서로 점검한다. 순서대로 적용하면 대개 1~2단계에서 45자 안에 들어온다.

1. **「적/의/것/들」** — 빼도 뜻이 유지되면 전부 제거
2. **번역투·조사구** (§2-1 표, §3) — ~에 대해/~을 통해/~할 수 있다 등 치환
3. **이중피동** — 단일피동으로
4. **문장 분리** — 그래도 넘으면 핵심 내용 하나만 남기고 나머지는 하위 `-` 항목으로 이동 (한 항목 = 한 핵심)

### 2-3. 적용 예시

| 단계 | 문장 | 글자수 |
|---|---|---|
| 원문(❌) | 이번 사업의 예산 집행 실태**에 대해** 면밀히 검토한 결과 다수**의** 문제점이 있는 **것으로** 확인되었음 | 52자 |
| 1단계(적/의/것/들 제거 + ~에 대해 삭제) | 이번 사업의 예산 집행 실태 검토 결과 문제점 다수 확인 | 31자 |
| 2단계(군더더기 추가 삭제) | 예산 집행 실태 검토 결과 문제점 다수 확인 | 24자 |

→ ⭕ **예산 집행 실태 검토 결과 문제점 다수 확인** (24자, 45자 이내 통과)

## 3. 번역투·군더더기 제거

### 3-1. 번역투 패턴 대조표

| ❌ 번역투 | ⭕ 대체 |
|---|---|
| ~에 의해 ~되다 | 능동문(~가 ~하다) |
| ~에 있다 | ~이다 |
| ~에 있어(서) | ~에서 / ~은·는 |
| ~을 갖다 (회의를 갖다) | 열다 / 하다 |
| ~에 위치한 | ~에 있는 |
| ~을 필요로 하다 | ~이 필요하다 |
| ~으로부터 | ~에서 |
| ~ 중에 있다 | ~하고 있다 / ~중 |
| ~한 관계로 | ~하였으므로 |

**예시**
- ❌ 본 계획은 관계 부서**와의** 협의**를 통해** 수립되었으며 향후 지속적인 관리가 필요**할 것으로 보임** (50자)
- ⭕ 본 계획은 관계 부서 협의**로** 수립, 향후 지속 관리 필요 (31자)

- ❌ 이번 조치로 민원 처리 기간이 단축**될 것으로 보여지며** 만족도도 개선**될 것으로 예상됨** (이중피동+서술식, 46자)
- ⭕ 이번 조치로 민원 처리 기간 단축, 만족도 개선 예상 (29자)

### 3-2. 의미 중복(군더더기) 제거

| ❌ 중복 표현 | ⭕ 하나만 남김 |
|---|---|
| 매~마다 | 매~ |
| 약~여 | 약~ 또는 ~여 중 하나 |
| 더 이상 | 이상 |
| 후 이내 | 이내 |
| 기간 동안 | 기간 또는 동안 중 하나 |
| 제공받다 | 받다 |

### 3-3. 명사 나열 — 개조식 항목에서는 완화

일반 서술문에서는 명사만 나열하면 의미가 불분명해지므로 금지 대상이지만, □○-* 개조식 항목은 원래 명사구 나열이 표준 형식이다. 다만 대상 간 관계가 실제로 불분명해지는 경우(무엇이 무엇을 하는지 안 보일 때)에는 최소한의 서술어(`~함`, `~됨`, `~로`)로 관계만 닫고 종결은 여전히 명사형으로 맞춘다.

- ❌ (관계 불분명) 예산 집행 지연 원인 분석 개선 방안 마련
- ⭕ (서술어로 관계만 닫음) 예산 집행 지연 원인을 분석해 개선 방안 마련

## 4. 두괄식 (요약 60~80자, 결론 선행)

요약박스는 배경·경위를 앞세우지 않는다. **무엇을 하는지(결론)를 첫 어절에 배치**하고 60~80자, 1~2줄 안에 끝낸다. 마커(□○- 등) 없이 순수 문장으로 쓴다.

**종결어는 보고의 실질에 맞춘다** — 단순 보고·공유는 `~보고드림`, 결정·승인·선택을 요청하는 검토·의사결정·품의 유형은 `~요청드림`(또는 `~요청함`)이 정확하다. 억지로 `보고드림`으로 통일하지 말 것. 판별: 요약의 결론이 "무엇을 했다/한다"면 보고드림, "무엇을 결정·승인·선택해 달라"면 요청드림.

| ❌ 배경 선행 (85자, 결론이 맨 끝) | ⭕ 결론 선행 (71자) |
|---|---|
| 최근 3개월간 예산 집행 현황을 점검한 결과 다수의 집행 지연 사례가 발견되어 이에 대한 원인을 분석하고 개선 방안을 마련하고자 이번 보고를 드리고자 함 | 예산 집행 지연 해소를 위해 배정 방식을 전면 개편, 상반기 중 신규 지침 마련·하반기 집행률 95% 달성을 추진하고자 보고드림 |

판단 기준: 요약문의 **첫 8~10자만 읽어도** "무엇을 하겠다는 보고인지" 파악되면 통과, 배경·경위·조사 결과부터 시작하면 실패.

## 5. "AI 티" — 이 장르에서 정답인 것 / 여전히 금지인 것

일반 산문에서는 "AI가 쓴 티"로 지적되는 요소(불릿 남발, 명사형 종결, 표, 굵게 강조)가 **공문서-개조식 장르에서는 오히려 표준 형식**이다. 반대로 장르와 무관하게 항상 금지인 요소(hype 어휘, 의미 과장, 이모지)는 그대로 금지다. 형식적 AI 티는 이 장르의 규범, 내용적 AI 티는 장르 불문 금지 — 이 한 줄이 판정 기준이다.

| 요소 | 일반 산문에서 | 이 장르(공문서-개조식)에서 | 판정 |
|---|---|---|---|
| 불릿·번호 목록 | AI 티로 지적됨 | □○-* 위계가 표준 형식 | ⭕ 정답 |
| 명사형 종결(~함/~예상) | 딱딱하다고 지적됨 | §1의 규범 그 자체 | ⭕ 정답 |
| 표 사용 | 남용 지적됨 | 결론(본문)의 근거 제시 수단으로 표준 | ⭕ 정답 |
| 소제목·계층 구조 | 과도한 구조화로 지적됨 | □(대제목)→○→-→* 위계가 필수 | ⭕ 정답 |
| 굵게 강조 | 남용 지적됨 | 문서당 핵심 결론 2회 이하로 절제 사용 | △ 조건부 허용 |
| **hype 어휘**(획기적·혁신적·게임체인저·역대급) | 지적됨 | 여전히 금지 — 판단 근거 없는 과장 | ❌ 금지 |
| **의미 과장**(주목할 만하다, 괄목할 만한 성과) | 지적됨 | 여전히 금지 — 수치·사실로 대체 | ❌ 금지 |
| **이모지** | 지적됨 | 여전히 금지 — 공문서 격식 위반 | ❌ 금지 |
| 상투적 메타발언("정리하면", "다음은 ~입니다") | 지적됨 | 요약박스(§4)가 이미 그 역할 → 중복이라 금지 | ❌ 금지 |
| 수사의문문("그렇다면 어떻게 해야 할까?") | 지적됨 | 공문서에 존재하지 않는 화법 | ❌ 금지 |
| 1인칭 소감("~라고 생각합니다/느낍니다") | 지적됨 | 공문서 주어는 기관·부서, 개인 소감 없음 | ❌ 금지 |
| 번역투(~에 대해/~을 통해) | 지적됨 | §2·§3에서 별도로 금지 | ❌ 금지 |
