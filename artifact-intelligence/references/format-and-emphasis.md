## 1. 강조 규칙 (기계 집행됨)

세 가지 인라인 강조 클래스만 존재한다. 셋 다 `<span class="...">텍스트</span>` 형태로 항목(`items[].html`)·요약(`summary`) 안에 심는다.

| 클래스 | 색 | 용도 | 판정 규칙 |
|---|---|---|---|
| `num` | 검정 볼드 | 일반 핵심 수치(금액·건수·비율·날짜 등) | 강조하고 싶은 수치의 기본값. 개수 제한 없음 |
| `delta` | 빨강 | **감소 방향** 수치 전용 | 텍스트에 `△`가 포함된 경우만 유지. `△` 없이 `delta`를 쓰면 조립기가 자동으로 `num`으로 강등한다 |
| `accent` | 남색 | 핵심 결론·판단·결정요청 문구(수치 아닌 문장 강조) | **문서당 2회 이하**. 3번째부터는 조립기가 span을 벗기고 평문으로 되돌린다(등장 순서 기준) |

기계 집행 로직(`assemble.py::enforce_emphasis`):
```python
# delta인데 △ 없으면 num으로 강등
t = DELTA_RE.sub(lambda m: m.group(0) if '△' in m.group(1)
                 else f'<span class="num">{m.group(1)}</span>', t)
# accent는 문서 전체 누적 2회까지만 유지, 3회차부터 태그 제거
def cap(m):
    nonlocal accents
    accents += 1
    return m.group(0) if accents <= 2 else m.group(1)
```

- 이 집행은 **본문 섹션 항목에만** 적용된다. 요약박스는 별도 규칙(§5)으로 강조 자체가 전부 제거된다.
- 생성 단계에서부터 규칙을 지켜라: `delta`는 감소·하락·축소를 나타낼 때만, 그것도 반드시 `△`를 텍스트에 포함해서 쓴다. `accent`는 문서 전체에서 정말 중요한 결론 1~2곳(대개 "시사점"·"향후계획" 섹션의 결정요청 문구)에만 예산을 아껴 쓴다.
- 증가 수치·긍정 수치는 `delta`가 아니라 `num`을 쓴다(`delta`=빨강은 감소 전용 색이다).

예시:
```html
매물 동향: 종료 직전 <span class="num">8.0만건</span> 정점 → 직후 <span class="num">6.6만건</span><span class="delta">(△4~5%)</span>
고정 운영시간이 오히려 <span class="accent">평일 오전 공석을 늘리는 구조</span>로 판단
```

## 2. 표기 규범

| 항목 | 규범 | 정규화(조립기 자동 처리) |
|---|---|---|
| **날짜(일 단위)** | `'26. 7. 23.` — 아포스트로피+2자리 연도, 마침표+공백으로 연·월·일 구분, 마지막 일 뒤에도 마침표 | `'26.7.23.`·`'26. 7. 23` 등 붙여쓴 입력도 `'(\d{2})\.\s*(\d{1,2})\.\s*(\d{1,2})\.` 정규식으로 표준형에 강제 정렬(`norm_rich`) |
| **날짜(월·분기 단위)** | 일(日)이 없는 시점은 `9월`·`3분기`처럼 그대로 쓴다. 연도가 문맥상 자명하면(보고일과 같은 해) 연도 생략, 다른 해면 `'27. 3월`·`'27년 3분기`로 연도 병기. 완전형 날짜 규범(마침표+공백)은 일 단위에만 적용 | — (자동 변환 없음, 생성 시점 규칙) |
| **금액 단위** | 본문 문장 안에는 단위를 붙여 쓴다(`8.0만건`·`4.1만원`). 표에서는 단위를 셀에 반복하지 않고 캡션 `(단위: 만건, %)`으로 일괄 표기 | — (생성 시점 규칙, 자동 변환 없음) |
| **△ 부호** | 감소 수치 전용 접두 기호. `△17.2`처럼 수치 앞에 붙이고 `delta` 클래스로 감싼다. 증가는 부호 없이 `num` | §1의 강등 로직이 `△` 유무로 delta/num을 가른다 |
| **가운뎃점** | 병렬 명사 사이 밀착 표기: `조직·예산`(앞뒤 공백 없음) | `\s*([·・])\s*` → `·`로 치환. `조직 · 예산`, `조직・예산` 등 입력해도 자동 밀착 |
| **붙임** | `붙임  <내용> <수량>부.  끝.` — 라벨과 "끝." 사이 내용은 반드시 수량(`1부`·`2매` 등)으로 끝나고 마침표, "끝."도 마침표 포함 | `norm_attach`: 앞의 `붙임:`·`별첨:` 라벨 중복 제거 → 끝의 `끝.` 중복 제거 → 마침표 제거 후 수량 패턴(`\d+\s*[부매]$`) 없으면 `1부` 자동 부여 → 마침표 재부착. 조립 후 최종형은 `<span class="label">붙임</span>&nbsp;&nbsp;{내용} 1부.&nbsp;&nbsp;끝.` |
| **요약박스 강조** | 요약(`summary`)에는 `num`/`delta`/`accent` 어떤 span도 남기지 않는다 | `SPAN_IN_SUMMARY` 정규식으로 요약 안의 모든 `<span class="...">…</span>`를 태그만 벗기고 텍스트만 남김 |
| **글머리 마커 중복** | 항목 텍스트 선두에 `○`·`-`·`□`·`ㅇ`·`※`·`·`·`•` 등을 직접 타이핑하지 않는다 — 마커는 CSS `::before`가 그린다 | `MARKER` 정규식으로 선두 마커 문자열을 제거(`norm_rich`). 직접 넣으면 마커가 이중 표시되므로 조립기가 제거하되, **생성 단계에서부터 넣지 않는 것이 원칙** |

## 3. 산출 형식 — 생성 JSON 스키마

콘텐츠 생성(3단계) 산출은 문서 배열(단일 문서도 배열 1개)로, `build/samples-docs.json`에 저장 후 `python3 build/assemble.py build/samples-docs.json`으로 조립한다.

문서에 `"purpose_type"` 필드(①~⑪, 빌드플랜의 보고목적 유형)를 넣으면 문체 게이트가 **요약 종결과 유형의 실질 정합**을 교차 점검한다(결정·승인 유형 ②⑩⑪인데 보고드림, 공유·기록 유형 ①⑤⑥⑧인데 요청드림 → soft 경고). 항상 넣는 것을 권장.

```json
[
  {
    "filename": "doc01-public-library-reading-room-usage",
    "title": "공공도서관 열람실 이용 현황 및 운영 개선 보고",
    "byline": "<시설운영처, '26. 7. 23.>",
    "summary": "관내 공공도서관 열람실 평균 이용률이 42.5%로 전년 대비 6.1%p 하락, 평일 오전 공석이 늘어 운영시간 조정 검토가 필요함",
    "sections": [
      {
        "heading": "이용 현황",
        "items": [
          { "level": 2, "html": "관내 <span class=\"num\">12개</span> 도서관 열람실 좌석 <span class=\"num\">1,480석</span> 기준 집계" },
          { "level": 3, "html": "이용 저조 시간대: 평일 09~12시 <span class=\"num\">31%</span>" }
        ]
      }
    ],
    "table": {
      "after_heading": "이용 동향 분석",
      "caption": "(단위: 천명, %)",
      "header": ["구분", "'25. 1~4월", "'26. 1~4월", "증 감"],
      "rows": [
        ["열람실 이용자 수", "96.4", "82.3", "△14.6"]
      ]
    },
    "attach": "도서관별 열람실 이용 현황 상세 자료 1부"
  }
]
```

필드 규격:

| 필드 | 타입 | 규칙 |
|---|---|---|
| `filename` | string | 확장자 없이. 조립기가 `samples/<filename>.html`로 저장 |
| `title` | string | 평문(태그 불가). `norm_plain` 처리 — HTML 이스케이프만 하고 span은 못 씀 |
| `byline` | string | 평문. 관례상 `<부서명, '26. 7. 23.>` 꺾쇠 포함 형태 |
| `summary` | string | span 입력 가능하지만 조립 시 전부 평문화됨(§5). 60~80자·1~2줄 예산은 `references/compress-and-budget.md` |
| `sections[]` | array | `heading`(대제목 텍스트, □ 마커는 CSS가 그림) + `items[]` |
| `sections[].items[].level` | 2\|3\|4 | 위계 단(§3-1 표 참조). `level:1`(□)은 `heading`이 대신하므로 items에는 안 씀 |
| `sections[].items[].html` | string | span(`num`/`delta`/`accent`) 포함 가능. 선두에 마커 문자 넣지 않음 |
| `table` | object\|null | 문서당 최대 1개(1p 표 1개 제한). 없으면 `null` |
| `table.after_heading` | string | 이 표를 삽입할 `sections[].heading`과 정확히 일치해야 그 섹션 뒤에 배치됨 |
| `table.caption` | string | 우상단 단위 표기, 예: `(단위: 만건, %)` |
| `table.header` / `table.rows` | string[] / string[][] | 셀은 전부 문자열. 숫자 비중 절반 이상인 열(첫 열 제외)은 조립기가 자동으로 우측정렬(`class="r"`) 부여 |
| `attach` | string | 라벨·끝 없이 내용만(`도서관별 열람실 이용 현황 상세 자료 1부`). `norm_attach`가 최종형으로 변환 |

### 3-1. level → 마커 대응

| level | 마커(CSS ::before) | 역할 |
|---|---|---|
| (heading, level 1 상당) | □ | 대제목 — `sections[].heading`으로 별도 지정, items에는 안 씀 |
| 2 | ○ | 주요 항목. 45자 이내 1줄 원칙(`references/compress-and-budget.md`) |
| 3 | - | 세부 내용 |
| 4 | * | 참고·비고 |

`LEVEL_CLS = {2: "i-l2", 3: "i-l3", 4: "i-l4"}` — level 값과 CSS 클래스가 1:1 고정 매핑이므로 스키마 밖 값(1·5 등)을 items에 넣지 않는다.

### 3-2. html 필드 인라인 span 클래스

항목 html에 쓸 수 있는 span은 `num`·`delta`·`accent` 세 가지뿐이다(§1). 그 외 임의 class·style·태그는 조립기가 걸러내지 않으므로 생성 단계에서부터 이 세 가지 외에는 넣지 않는다.

## 4. 컴포넌트 규격 요약 — "무엇을 채우는가"

색·선굵기·여백 등 시각 스펙은 `build/tokens.css`·`build/report.css`가 고정 담당한다. 콘텐츠 생성자가 채워야 할 것만 정리한다.

| 컴포넌트 | 채우는 필드 | 콘텐츠 규칙 |
|---|---|---|
| **제목부** | `title`, `byline` | `title`은 명사구, 표 안 중앙 배치(상하 청색바 사이). `byline`은 제목 아래 우측, `<부서명, 날짜>` 형태 |
| **요약박스** | `summary` | 60~80자·1~2줄, 두괄식(결론 선행), "~보고드림" 류 종결. 내부는 무강조(§5) |
| **표** | `table.caption`, `table.header`, `table.rows` | 문서당 1개, 3~5열 권장. 캡션에 단위(단위 없는 질적 표는 캡션 생략 — `caption: ""`), 숫자열은 조립기가 자동 우측정렬하므로 정렬 지정 불필요. 대안 비교 문서에서 비용·기간 등 비교 속성은 본문 항목이 아니라 표의 행으로 집약(FB-018) |
| **붙임** | `attach` | 내용 + 수량만 채우면 됨. 라벨(`붙임`)·구분자(`&nbsp;&nbsp;`)·"끝."은 조립기가 고정 부착 |

## 5. 요약박스(글상자) 내부 무마커 규칙

요약박스는 본문과 다른 두 가지 특례를 갖는다.

1. **글머리 위계 금지**: 요약박스 안에는 □○-* 어떤 마커도 쓰지 않는다. 무마커 문장형이 기본이며, 나열이 꼭 필요하면 본문 위계와 겹치지 않는 ◇·◈ 계열만 예외로 허용한다.
   [근거: prototype/1p/README.md "사용자 피드백 반영" 2번 — "글상자 안에서는 본문 글머리 체계(□○-)를 쓰지 않는다. 무마커 문장형이 기본, 나열이 필요하면 본문과 겹치지 않는 ◇·◈ 계열만"(실무자 증언 + 작성지침 샘플 근거, 귀납·코퍼스 검증 대기)]
2. **강조 전부 해제**: `summary`에 `num`/`delta`/`accent` span을 입력해도 조립 시 태그만 벗겨지고 텍스트만 남는다(`SPAN_IN_SUMMARY` 치환). 요약박스 자체가 이미 음영·테두리로 강조돼 있으므로 내부 강조는 시각적 이중 강조가 되어 제거한다.
   [근거: prototype/1p/README.md "13종 전수 검증 라운드" — "요약박스 무강조화"가 정규화 계층에 편입; assemble.py `SPAN_IN_SUMMARY.sub(r'\1', ...)`]

생성 단계 실무 지침: `summary`를 쓸 때는 애초에 span을 넣지 않는 것이 가장 안전하다. 넣어도 최종 출력에서는 사라지므로 강조가 필요한 핵심 수치는 반드시 본문 섹션(`sections[].items[].html`)에 배치한다.
