description: 문서지능 — 공공기관 문서(보고서·시행문·규정·보도자료·슬라이드)를 바로 완성하거나, 함께 검수하며 만듭니다
---

`artifact-intelligence` 스킬로 대한민국 공공기관 문서를 만든다. **SKILL.md 의 "작업 흐름 — 두 방식: 바로 완성 / 함께 검수" 를 그대로 따른다.** 방식은 사용자가 고른다 — **바로 완성**은 검수 없이 끝까지 가서 파일과 '확인할 것'을 끝에 알리고, **함께 검수**는 아래 ⏸ 에서 멈춰 사람의 확인을 받는다. 두 방식 모두 게이트(승인된 빌드플랜·문체·조판·지어냄 검사)는 그대로다.

1. **0단계 먼저 — 버전 확인**: 설치본이 최신인지 대조하고(설치 `.claude-plugin/plugin.json` vs 공개 마켓 `marketplace.json`), 뒤처졌으면 갱신을 안내한다. 요청·자료가 아직 없으면 **"의도 한 줄 + 자료"** 를 청한다(자료는 텍스트·파일 첨부 모두 가능).
2. **방식 정하기**: 방식은 **에이전트가 대화를 읽고 정한다**('바로·빨리·그냥 만들어·검수 없이·알아서' → 바로완성, '편집기로·같이 보면서·검토하며·확인하면서' → 함께검수). `workmode`(작업방식, 결정=보기, work_mode=정한 방식 — 못 정했으면 비움, 요청=요청 한 줄)를 부르고 값의 방식을 따른다(넘긴 방식 → 이 대화에서 정한 방식 → 저장된 선택; 값.힌트는 참고일 뿐 방식을 이기지 않는다). 물을까=true면 **그때 한 번만** 두 선택지와 '앞으로도 이대로'를 묻는다. 답도 에이전트가 읽어 고른 쪽을 work_mode 에 싣는다 — 이번만이면 결정=보기, '앞으로도 이대로'면 결정=저장(저장은 work_mode 필수).
3. **장르는 에이전트가 요청을 읽고 정한다** — 문서 종류를 말했으면 그 장르('보도자료로 정리해 주세요'→보도자료, '공문으로'→시행문, '규정 만들어'→규정, '슬라이드로'→발표 슬라이드 — 말과 장르 등록부의 대응표는 SKILL 2절), 이름이 둘 이상이면 요청의 목적어(만들 문서)를 따르고, 말이 없으면 내용으로. `detect`(판정, request=요청 한 줄)의 점수는 1페이지 보고서 안에서 보고목적 유형을 고를 때만 쓴다(값.명시장르는 참고). 함께 검수: **⏸ 장르·유형을 보여주고 "이대로 진행할까요?" 확인** / 바로 완성: 1페이지 보고서 유형은 1위가 뚜렷하면 1위로, 약하면(1위 점수 1 이하·차점과 2 미만) 요청 문장을 읽어 상위 3개 가운데 고르고 끝 보고에 적는다. CLI 로 부를 때는 정한 방식을 뒤 호출에도 `work_mode`로 싣는다(CLI 는 대화를 기억하지 않는다).
4. **빌드플랜 설계 → 승인**: `composeplan`(설계지시문내기)로 구성 계획을 짜 `saveplan`(플랜저장)→plan_id. 함께 검수: **⏸ 사용자에게 보여 `approveplan`(플랜승인) '승인'** 을 받는다 / 바로 완성: 에이전트가 `approveplan`을 직접 부른다(코멘트 '바로 완성 — 에이전트 자동 승인'). 승인 없으면 새문서·조립이 게이트에 막힌다(강제 관문).
5. 승인된 **plan_id 를 doc 에 넣어** `compose` 지침대로 초안을 쓰고 `new`(검사 true, 원문 포함 — 따로 준 자료가 없으면 요청 글을 원문으로; 원문 없이 만든 문서는 `export`가 거절한다)로 `stylelint`·`gate`·`fabcheck` 3중 검사를 통과시킨다. 자료 값으로 셈한 합계·비율은 doc 의 `산출`에 식을 적는다(`{"값": "62.5%", "식": "5/8"}`). 바로 완성은 사유대로 스스로 고쳐 **최대 3회** — 못 넘으면 내보내지 않고 까닭과 '함께 검수로 이어 갈까요'를 알린다.
6. 함께 검수: **⏸ 편집기를 연다** — `editor`(편집기열기 · 인자 key)를 불러 편집 화면을 **사용자의 실제 브라우저**에서 연다(로컬 편집기 서버 127.0.0.1 을 잠깐 띄운다 — 저장=정본 즉시 반영·되돌림 지점(이력)·AI 다시쓰기가 다 산다). 자동 열기가 안 되면 돌려준 URL 을 전한다. 사람이 직접 리터칭한다. "이대로 좋다" 확인 전에는 내보내지 않는다. / 바로 완성: 편집기는 사용자가 "편집기 열어줘"라고 할 때만 연다.
7. `export` 로 내어 전달한다(지금 판이 검사를 통과한 기록이 있어야 낸다 — 사람이 고친 판은 다시 잰다. override_reason 은 사람이 명시적으로 원할 때만 쓰고 끝 보고에 적는다). 함께 검수: **⏸ 승인 후에만**, 모든 형식을 한 번에 뽑으려면 `export` 형식="전부". / 바로 완성: 곧바로 — 요청한 형식, 말이 없으면 A4 장르는 pdf·hwpx, 슬라이드는 pdf·pptx(형식마다 한 번씩). 끝 보고는 SKILL.md 4절 그대로: 만든 파일(절대 경로 = `export` 값.파일, 내보낸 것만 사는 build/exports) · 한 줄 요지 · 빈칸(자리표시)이 남았으면 맨 앞에 · **확인할 것**(`new` 결과의 `확인할것` 목록 + 가정한 값·추론한 문장·다르게 고른 유형·못 낸 형식) · 늘 싣는 한 줄 "숫자는 자료와 대조했지만 모든 표기를 다 잡지는 못합니다. 금액·기간·날짜는 자료와 한 번 맞춰 봐 주세요." · "편집기로 다듬으려면 '편집기 열어줘'". 검사 기록 파일(workspace/검사기록.json·검사자료.json)은 직접 고치지 않는다.

사용자가 이미 이 명령과 함께 의도·자료를 준 경우($ARGUMENTS), 0단계(버전 확인)만 마치고 그 인자를 읽어 방식을 정한 뒤(2번) 바로 3번(판정)부터 시작한다. 자료에 없는 수치·이름은 지어내지 않는다(모르는 값은 반드시 ○○ 한 꼴로 비운다) — 함께 검수는 필수 입력이 비면 되묻고, 바로 완성은 ○○로 비워 끝 보고에 올리며 기본값으로도 풀 수 없을 때만 묻는다.
