# 문서지능 · Artifact Intelligence

## 무엇을 하는 스킬인가

한국 공공기관 문서의 시각 품질을 그대로 재현하되, **꾸미기는 스킬이 하고 사람은 내용에만 집중한다.** 사용자에게 받는 것은 "무엇을·누구에게·왜 보고하는가(의도)"와 "재료가 되는 사실·수치(자료)"뿐이다. 목차 구성, 문장 다듬기, 개조식 변환, 조판, 분량 맞춤, 한글 변환은 전부 규칙에 따라 자동 처리한다.

## 문서는 이 컴퓨터에서 만든다 — 규칙도 이 설치본에 있다

판정·작성·조립·문체검사·조판·한글 변환까지, 문서를 만드는 일은 **전부 이 설치본에서(로컬) 돈다.** 사용자의 자료·초안·완성 문서는 **이 컴퓨터를 떠나지 않는다** — 서버로 올리지 않는다. 규칙의 정본인 온톨로지(`ontology/ontology.json`)도 이 설치본에 함께 있고, `지식`은 그 파일을 로컬에서 읽는다. 그래서:

- **규칙 수치·판별 기준을 이 문서에 옮겨 적지 않는다.** 정본은 `ontology/ontology.json` 이고, 문서마다 필요한 작성 지침은 `compose`(프롬프트조립) 도구가 거기서 뽑아 담아 준다 — 지침은 그 도구에서 받는다.
- 예외 하나: 편집 화면의 'AI로 고치기'를 사용자 API 키 없이 쓰면, 고른 글 조각(표 셀 포함)만 정책 서버의 모델로 보내 고친다. 사용자 키를 넣으면 그 키로 브라우저가 직접 부른다.

## 작업 흐름 — 두 방식: 바로 완성 / 함께 검수

- **바로 완성** — 검수 없이 AI가 끝까지 만들어 파일로 낸다. 확인할 곳은 끝 보고에 모은다.
- **함께 검수** — 판정 확인·구성 승인·편집기 리터칭·내보내기 승인에서 멈춘다(웹앱과 같은 흐름).

두 방식 모두 **게이트는 그대로다** — 승인된 빌드플랜(plan_id), 문체·조판·지어냄 검사. 플러그인의 `export`는
**지금 판이 검사를 통과한 기록**이 있어야 낸다. **강행이유는 사람이 명시적으로 원할 때만** 적고(에이전트가 스스로
적지 않는다), 썼으면 끝 보고에 반드시 그 사실과 이유를 적는다. 원문(자료) 없이 만든 문서도 내보내지 않는다 —
따로 준 자료가 없는 요청이면 **요청 글을 원문으로** 넘긴다. 관문은 이 컴퓨터에서 도는 도구의 약속이다 —
환경변수(`문서지능_표면`·`문서지능_웹앱`)를 바꾸거나, 산출 HTML 을 직접 고치거나(`export`가 거절한다), 검사 기록 파일
(`workspace/검사기록.json`·`workspace/검사자료.json`)을 직접 고치거나 지우지 않는다. 도구가 막지 못하는 길도 같은 약속이다
(로컬 도구의 한계): `python -c`로 api 를 바로 불러 관문을 끄는 것, 첫 원문에 자료 밖 줄을 덧붙이거나 초안 글을 원문으로
주는 것, 원문 없이 만든 뒤 나중에 원문을 처음 주는 것, 표·막대의 행 사이 값 맞바꿈(수는 모두 자료에 있다) — 하지 않는다.
지어냈나는 수를 배율(십·백·천·만·억·조)·단위(%·%p·원·명·건·개·곳)와 함께 견주지만 이 단위 밖으로 바꾼 것('1.5배'→'1.5%',
'3년'→'3개월', 원→달러), 셈 단위끼리 바꿈(건↔곳), 한글 수사('사천팔백억 원'·'수억'), 배율 목록 밖 글자('1조'→'1경'),
단위 머리 표('단위: 만원')에서 배율을 뗀 값('4,800'→'4,800원'), 괄호 속 단위('2(억 원)'), 자료 날짜의 숫자를 분기('4. 30.'→
'4분기')·다른 날짜('3. 2.~4. 30.'→'4. 3.')로 쓴 것, 증감 방향 뒤집기('감소'→'증가'), '3분의 2' 같은 분수 해석, 문장 안 수의
차례 바꿈은 보지 못한다. 거꾸로 머리 단위를 옮겨 맞게 쓴 값('(단위: 백만원) 250'→'2.5억')과 시각 꼴 바꿈('14:00'→'오후 2시')은
걸린다 — 자료와 같은 방향·같은 단위·같은 꼴의 아라비아 숫자로 옮기고, 날짜의 'N일'은 달을 붙여 쓴다('4월 30일까지').
검사 기록은 **잰 판의 내용 지문**(재기 시작 때의 문서 JSON·조립 HTML)에 묶인다 — 잰 뒤에 내용이 바뀌면(편집기 자동
저장 포함) 그 기록은 지금 판의 것이 아니고, 재는 도중 바뀌면 기록하지 않는다(도구가 "도중 바뀌었습니다"라고 알린다). 그때는 지금
판에 다시 잰다. 검사용 PDF 는 `workspace/_검사/`에, 에이전트가 `export`로 낸 파일은 `build/exports/`(값 `산출물자리`)에
생긴다. 사람이 편집기 화면에서 내보낸 파일은 이 관문 밖이라(막지 않고 검사 상태만 알린다) 자리도 따로다 — 작업 자리
`build/samples/`(조립 HTML 도 거기 있다, 검사에 걸린 판 포함).
도구는 MCP로 붙거나(플러그인) CLI로 부른다: `python3 workspace/api.py <작업> '<인자 JSON>'` — CLI 도 MCP 영문 인자
이름(`format`·`comment`·`source_text` …)을 받는다. 같은 인자를 한글·영문 두 이름으로 함께 싣지 않는다(값이 다르면 뒤의
것을 쓰고 경고한다).

### 0. 진입
먼저 설치 버전이 최신인지 본다 — bootstrap 로그에 "새 버전" 안내가 있었으면 갱신을 권하고, 확실치 않으면
`.claude-plugin/plugin.json`의 version 과 공개 마켓(`raw.githubusercontent.com/Kminer2053/Artifact-Intelligence-public/main/.claude-plugin/marketplace.json`)을
대조한다. 요청·자료가 없으면 "**의도 한 줄 + 자료**"를 청한다.

### 1. 방식 정하기 — `workmode`
- **방식은 에이전트가 대화를 읽고 정한다.** 사용자가 "바로·빨리·그냥 만들어·검수 없이·알아서"라고 했으면
  바로완성, "편집기로·같이 보면서·검토하며·확인하면서"면 함께검수. 요청마다 `workmode`(결정 `보기`,
  `work_mode`=정한 방식 — 못 정했으면 비움, 요청=요청 한 줄)를 부르고 값의 `방식`을 따른다. 코어는 넘긴
  방식 → 이 대화에서 정한 방식 → 저장된 선택 차례로 정한다.
- 값의 `힌트`는 코어가 요청 말투로 짐작한 것일 뿐이다 — 방식을 이기지 않는다. 주제어("검토 없이 진행된 사업")나
  참고 말("사례를 보며")을 방식으로 읽지 않는다.
- `물을까`=true면 **그때 한 번만** 묻는다: 두 선택지 + "앞으로도 이대로". 한 대화에서 두 번 묻지 않는다.
  권하는 물음(그대로 써도 된다): "어떻게 만들까요? 1) 바로 완성 — 검수 없이 끝까지 만들어 파일로 드립니다. 확인할
  곳은 끝에 모아 알려 드립니다. 2) 함께 검수 — 구성안을 먼저 보여 드리고, 편집 화면에서 같이 다듬은 뒤 내보냅니다.
  다음에도 같은 방식으로 하시려면 '앞으로도 이대로'라고 덧붙여 주세요."
- **CLI 는 대화를 기억하지 않는다** — 부를 때마다 새 프로세스라 `물을까`가 매번 true 일 수 있다. 이 대화에서 이미
  물었거나 정했으면 다시 묻지 말고 그 방식을 싣는다. 정한 방식은 뒤 호출(`new`·`save`·`editor`·`export` …)에도
  `work_mode`로 싣는다 — 안 실으면 도구 안내가 두 방식을 다 적는다. MCP 는 이 대화의 방식을 2시간(무활동) 기억한다.
- "이번만 바로, 다음엔 다시 물어봐"면 이번은 결정 `보기`+`work_mode`, 이 문서를 마친 뒤 결정 `지우기`.
- 답도 에이전트가 읽는다 — "바로 완성은 싫고 함께 검수로", "그냥 2번", "검수 없이 하는 건 불안해서 2번"처럼
  부정·번호·까닭이 섞여도 사용자가 고른 쪽을 `work_mode`에 싣는다. 이번만이면 결정 `보기`, "앞으로도 이대로"면
  결정 `저장`. 코어는 요청 글만으로 저장하지 않는다(저장은 `work_mode` 필수). "이번엔 편집기로 보자"는 저장하지
  않는다. "다시 물어봐"는 결정 `지우기`.
- 웹앱·공유 MCP(여러 사람)에서는 저장하지 않는다(거절된다).

### 2. 공통 단계 — 도구 쓰는 법은 두 방식이 같다
1. **접수** — 독자(누가 읽고 판단하나)·목적(읽고 무엇을 하나)·상황(계기)을 정한다.
2. **판정** — **장르는 에이전트가 요청을 읽고 정한다.** 사용자 말을 장르 등록부 이름으로 옮기는 표:

   | 사용자 말 | 장르(등록부) |
   |---|---|
   | 보도자료·보도·언론 배포 | `press` |
   | 공문·시행문·협조 요청·안내 공문 | `gongmun` |
   | 규정·내규·지침·규칙·요강·운영기준 | `regulation` |
   | 발표·슬라이드·PPT·프레젠테이션·설명회 자료 | `slides` |
   | 풀버전·상세 보고서·여러 쪽 보고 | `fullreport` |
   | 1쪽·한 장·요약 보고·보고서(말이 없으면) | `samples` |

   둘 이상이면 요청의 목적어(만들 문서)를 따른다 — "규정 개정 내용을 알리는 공문 써 줘"→`gongmun`, "규정안 검토
   보고서"→`samples`, "프레젠테이션 대신 보도자료로"→`press`. "보도자료는 필요 없고 공문"처럼 부정한 이름은 빼고,
   "첨부는 보도자료입니다"처럼 자료를 설명하는 말은 요청이 아니다. 표의 말이 하나뿐이어도 주제로 쓰였으면("보도 계획을 보고
   드릴 자료", "언론 보도 현황을 한눈에 보고") 만들 문서가 아니다 — 요청이 만들라는 문서(여기서는 보고 → `samples`)를
   따른다. 표의 말이 없으면 내용으로 고른다. `detect`(자료,
   `request`=요청 한 줄)의 점수는 **1페이지 보고서 안**에서
   보고목적 유형(①~⑫)을 고를 때만 쓴다 — 장르 점수는 자료 신호를 센 참고다(1페이지 보고서 기본값 점수가 1위로
   보이기 쉽다). 값 `명시장르`도 참고일 뿐이다.
3. **설계** — `composeplan`으로 빌드플랜(어떤 절을 어떤 순서로, 어디에 표·도식)을 짜 `saveplan` → plan_id →
   `approveplan`으로 승인을 기록한다(서버 기본 모델이 있으면 `drawplan`이 대신 짜 준다). 승인 없는 plan_id 면
   `new`가 막힌다.
4. **초안** — plan_id 를 doc 에 넣어 `compose` 지침대로 쓰고 `new`(검사 `true`, 원문=자료 원문 전체 문자열)로
   등록·조립한다. 첫 `new`에 받은 자료를 그대로 싣는다 — 플러그인은 문서마다 **처음 받은 원문**을 보관해 뒤
   검사를 그 원문으로 잰다(원문을 빼거나 바꿔도 걸림이 풀리지 않는다). 따로 준 자료가 없으면 요청 글을 원문으로
   넘긴다(원문 없이 만든 문서는 `export`가 거절한다). CLI 는 파일읽기로 읽은 파일 이름을 `자료파일`(source_files)로
   함께 넘긴다(`save`도 같다 — 첨부 사진 알림을 이 목록으로 센다). 자료에 없는 수치·이름·날짜는 지어내지
   않는다 — 모르는 값은 반드시 ○○ 한 꼴로 비운다(〇〇·OO·XX·[ ]·빈 밑줄 같은 다른 꼴을 쓰지 않는다 — 끝 보고의
   '채울 곳'은 ○○와 흔한 변형만 센다). 자료 값으로 셈한 합계·비율·차이는
   doc 최상위 `산출`(슬라이드 v2는 그 장의 `산출`)에 `{"값": "62.5%", "식": "5/8"}`처럼 식을 적는다 — 식의 수가
   자료에 있고 계산이 맞아야 지어냈나가 통과시킨다.
5. **검사·고치기** — `new` 값의 문체검사·조판게이트·지어냈나·지어냈나확장(슬라이드 v2는 hard 목록)을 사유대로
   고친다. 다시 잴 때는 첫 `new`가 돌려준 `key`를 doc.filename 에 넣고 같은 plan_id 로 `new`를 다시 부르거나
   (filename 을 비우면 -2·-3 새 문서가 쌓인다) `save`(검사 `true`·원문)를 쓴다. 확장 지어냄은 `fabfix`→`fabfixapply`
   (걸린 칸만 고친다). 내용이 바뀌면 검사 기록이 비므로 고친 뒤에는 늘 다시 잰다.
6. **편집기** — `editor`(key)가 로컬 편집기 서버를 띄워 사용자 브라우저에서 연다(저장·이력·AI 다시쓰기가
   웹앱처럼 정본에 반영된다). 자동으로 못 열면 돌려준 URL 을 사람에게 전한다. `file://`로 열지 않는다.
   「AI에게 고쳐달라」 지시는 1페이지 보고서면 `backtrace` scan→adopt, 다른 장르면 `history`(key)의
   처리='대기' 지시를 읽어 JSON 을 고쳐 `save`. 낸 HTML 은 `resume`으로 이어 고친다. 사람이 고친 판은
   내보내기 전에 다시 잰다.
7. **내보내기** — `export`(형식 하나, 또는 "전부" — A4 장르는 HTML·PDF·HWPX·MD·JSON, 슬라이드는
   HTML·PDF·PPTX·MD·JSON). `필요한것`="검사 통과"로 막히면 걸린 것을 고쳐 다시 잰다.

### 3. 함께 검수 — ⏸에서 멈춘다
**사람 승인 없이 최종 파일을 뽑아 전달하지 않는다** — 특히 편집기를 건너뛰고 바로 내보내지 않는다.
- ⏸ **판정**(2) — 결과를 보여 "이 장르·유형으로 진행할까요?"를 묻는다. 점수 차가 2 미만이거나 신호가 약하면 고르게 한다.
- ⏸ **구성 승인**(3) — 계획(`plan` 승인화면 HTML 또는 절 목록 요약)을 보여 주고, 좋다고 하면 `approveplan`.
- ⏸ **편집기**(6) — 검사를 통과하면 `editor`로 열어 사람이 다듬게 한다. 열 수 없는 환경이면 요약을 보여
  "고칠 곳 있으세요?"로 받는다.
- ⏸ **내보내기**(7) — "이대로 좋다"를 받은 뒤에만. 더 고칠 곳이 나오면 6으로 돌아간다. 사람이 편집기에서 넣은
  값이 지어냈나에 걸리면 사람에게 확인받고, 사람이 그대로 내라고 하면 `강행이유`에 그 확인을 적는다.

### 4. 바로 완성 — 멈추지 않고, 확인할 곳은 끝에 모은다
- **접수·판정** — 모호하면 흔한 기본값으로 정해 '가정한 값'에 적는다. 장르는 위 2의 규칙대로 요청을 읽고 정한다
  (점수 1위로 가지 않는다). 1페이지 보고서면 보고목적 유형은 `detect` 점수로: 1위가 뚜렷하면 1위, **1위가
  약하면**(1위 점수가 1 이하이거나 차점과 2 미만) 요청 문장(결과·계획·승인 요청 …)을 읽어 상위 3개 가운데
  맞는 유형을 고르고, 끝 보고에 적는다(예: "판정 1위는 ⑪ 품의였지만 요청이 결과 보고라 ⑥으로 썼습니다").
  슬라이드 목적도 요청으로 정한다(승인·투자 요청이면 설득). 장르나 유형이 전혀 갈리지 않을 때만 묻는다.
- **설계** — `approveplan`을 에이전트가 부른다(status `승인`, 코멘트 `바로 완성 — 에이전트 자동 승인`).
  승인화면은 띄우지 않고, 플랜의 `요구분석.확인필요`는 기본값으로 정해 '가정한 값'에 적는다.
- **고치기 — 최대 3회.** 3회 안에 못 넘으면 깨진 파일을 내보내지 않는다 — `강행이유`로 넘기지 않고 까닭을 알린
  뒤 "함께 검수로 이어서 편집 화면에서 다듬을까요?"라고 묻는다. 셈한 값이 걸리면 `산출`에 식을 적거나 자료대로 고친다.
- **내보내기** — 요청한 형식으로, 말이 없으면 A4 장르는 `pdf`·`hwpx`, 슬라이드는 `pdf`·`pptx`(형식마다 한 번씩).
  HWPX가 표준 양식 밖 서식으로 막히면 PDF는 내고 끝 보고에 적는다.
- **끝 보고**
  - 만든 파일 — 절대 경로(`export` 값 `파일`; 내보낸 것만 사는 `build/exports/` = `workmode` 값의 `산출물자리`).
  - 한 줄 요지.
  - **빈칸이 남았으면 맨 앞에** — `확인할것`의 '빈칸(○○)'(○○·OOO·YYYY. MM. DD.·(미정)·추후 확정·TBD·N곳·제N조·
    협의 중 …)은 자리표시가 남은 채 낸 곳이다. 끝 보고 첫머리에 "채울 곳 N곳"으로 먼저 적는다(내보내기는 막지 않는다).
    코어가 세는 꼴은 ○○와 흔한 변형(〇〇·OO·XX·○○○·[ ]·{ }·`<기관명>`·`[담당자]` 같은 자리 이름·빈 밑줄)뿐이다 —
    △△·□□·전각 ＯＯ·소문자 ooo·빈 괄호 `(  )` 같은 다른 꼴은 세지 못하니, 스스로 비운 칸은 ○○로만 비우고 끝 보고에도 적는다.
  - **확인할 것** — 마지막 `new`·`save` 결과의 `확인할것` 목록을 그대로 옮긴다(지어냄 의심·고친 곳(지어냄 의심으로
    고친 값)·지어냈나 건너뜀·어긋남 두 값·확인 물음·셈한 값과 식·AI 그림·속성거부·자동 교정·조립기가 채운 칸·경고·
    빈칸 ○○; 80건을 넘으면 끝 줄 '외 N건'). 코어가 모르는 것만 더한다: 가정한 값(공개 구분·보존기간·수신 같은 메타
    기본값 포함) · 자료에서 추론해 쓴 문장 · 판정과 다르게 고른 유형·차점 · 못 낸 형식과 그 까닭 · `강행이유`를
    썼다면 그 사실과 이유.
  - **쓰지 못한 첨부 사진** — MCP·CLI 모두 옮긴다(사용자가 사진을 넣어 달라고 했으면 첫머리 가까이). 마지막 `new`·`save`
    결과의 `확인할것`에 사진 줄이 있으면 **그대로** 옮긴다 — '첨부한 한글(·워드) 문서 N개에 든 사진 M장은 쓰지 않았습니다 …',
    '함께 올린 PDF에서 사진 N장을 찾았습니다. 문서 속 사진과 같은지 편집 화면에서 확인해 주세요.', '첨부한 한글 문서에 사진이
    들었을 수 있습니다 …', '그림을 처리하는 도구가 없어 올린 사진을 쓰지 못했습니다 …', '(파일 이름): 그 파일을 처리하지
    못했습니다 …'(도구 없음이 아니다 — 그 파일만 다시 올려 보게 한다), '(파일 이름): 이 파일에서 사진을 꺼내다 멈춰서 …'·
    '(파일 이름): 이 사진 파일을 열지 못해 …'(그 파일은 다시 올려도 같다 — 줄이 권하는 대로 사진 파일로 따로·다시 저장해 올리게 한다),
    '이 문서 종류에는 사진을 넣는 자리가 없어 첨부 사진을 싣지 않았습니다.'·'… 올린 사진을 싣지 않았습니다.'(1p·시행문·규정·판형 v2). 줄마다 따로 센 값이다 — 문서 속 사진 수는 사진 파일·PDF 를
    함께 올렸어도 줄이지 않는다(같은 사진인지는 사람이 편집 화면에서 본다). 시스템은 이 문서에 묶인 파일(이 대화에서 읽은
    자료·`자료파일`·문서가 쓴 그림의 파일)로 센다. 줄이 없으면 쓰지 않는다.
    MCP 는 파일읽기의 `그림안내`를 끝 보고에 옮기지 않는다(그 파일 하나만 본 값이다). **CLI 는 `new`·`save`에 파일읽기로
    읽은 파일 이름을 모두 `자료파일`(source_files)로 늘 넘긴다** — CLI 는 대화를 기억하지 않아, 넘기지 않으면 원문에 본문이
    통째로 든 자료만 센다. 그래도 새문서(`new`·`save`) `확인할것`에 사진 줄이 없으면 파일읽기 `그림안내` 줄을 옮긴다. 두 줄이
    다 있으면 새문서 것을 옮긴다. 파일읽기의 `에이전트` 칸은 사용자에게 옮기지 않는다(에이전트에게 하는 말이다).
    - 한글·워드 문서(HWP·HWPX·DOCX) 속 그림은 꺼내 쓰지 않는다. **에이전트가 문서를 풀어(zip·kordoc) 속 원본을 꺼내 올리지
      않는다** — 속 원본은 화면과 다를 수 있다(가린 자리·자른 바깥·지운 변경이 되살아난다).
    - 넣으려면 **한글(워드)에서 PDF로 저장해 함께 올리면 보이는 그대로 쓴다** — 시스템이 PDF 에서 보이는 자리만 잘라 그림
      목록에 올린다. 아니면 사진 파일(PNG·JPG)로 올려 달라고 한다. '그림을 처리하는 도구가 없어 …' 줄이 섰으면 PDF·사진
      파일 길도 쓸 수 없다 — 그 줄(bin/bootstrap.sh·관리자 안내)만 옮기고 다른 길을 권하지 않는다.
  - 늘 싣는 한 줄(확인할 것이 비어도): "숫자는 자료와 대조했지만 모든 표기를 다 잡지는 못합니다. 금액·기간·날짜는 자료와 한 번 맞춰 봐 주세요."
  - 끝 줄: "편집 화면에서 더 다듬으려면 '편집기 열어줘'라고 해 주세요." — 그러면 `editor`로 열고, 고친 뒤
    다시 재서 `export`를 다시 부른다(먼저 낸 파일은 옛 판이다).

## 되묻기는 강제된다

자료끼리 어긋나거나(`conflicts`) 구성 설계가 승인되지 않았으면 코어가 작업을 막고 물음을 돌려준다. 답이 실리기
전에는 다음으로 가지 않는다 — **결론을 창작하지 않는다.** 두 방식 모두 자료 밖 사실을 지어내지 않는다.

- **함께 검수**: 답은 사람이 한다. 멈춤 지점(⏸)도 같은 규율이다.
- **바로 완성**: 어긋난 값은 한쪽을 고르지 않는다 — 그 자리를 ○○로 비우고 어긋남답에 "미정(○○) — 끝 보고에서
  확인"을 싣는다(두 값은 `확인할것`의 '어긋남'으로 끝 보고에 오른다). 기본값으로도 풀 수 없을 때(유형이 전혀
  갈리지 않는 등)만 그때 묻는다.

## 장르 — 여섯

1페이지 보고서 · 풀버전 보고서 · 시행문(공문) · 규정 · 보도자료 · 발표 슬라이드. 흐름은 모두 같다(판정 → 지침 → 초안 → 조립·게이트 → 내보내기). 발표 슬라이드만 세로 A4가 아니라 가로(16:9)라 산출이 PPTX다. **다른 것은 규칙뿐**이고, 그 규칙은 `compose`에 `장르`(예: `"gongmun"`)를 넘기면 완성 지침에 실려 온다. **이 '장르' 값은 사람이 읽는 문서 이름이 아니라 등록부 이름이다**(1페이지 보고서→`samples`, 풀버전 보고서→`fullreport`, 시행문(공문)→`gongmun`, 규정→`regulation`, 보도자료→`press`, 발표 슬라이드→`slides`) — `새문서`·`저장`·`문체검사`·`조판게이트`·`판정`(예시 인자 안) 등 `장르`를 받는 모든 작업이 같다. 장르마다 문체·구성이 크게 다르므로(예: 시행문은 개조식이 아니라 서술어 완결·공손체) 반드시 그 문서의 `compose` 지침을 따른다. 어떤 장르가 있는지는 `문서목록`으로 본다 — 목록을 여기 손으로 적지 않는다.

## 알아둘 것

- **이미지·도식**: 도식·차트·구조는 지어내지 말고 그림 도구로 그리거나, 올린 첨부의 그림을 쓴다. AI 생성 이미지에는 렌더에서 'AI 생성물' 표기가 강제로 붙는다.
  - **첨부 그림은 목록 id 로만 고른다.** 시스템이 올린 자료에서 그림을 꺼내 목록 카드를 만든다(`figures`, 파일읽기 결과의 `그림`, 지시문의 [올린 자료 속 그림]). 목록에는 **이 대화에서 올리거나 읽은 자료와 이 문서에 묶인 자료의 그림만** 오른다(다른 대화의 첨부는 없다 — 쓸 자료는 파일읽기로 읽는다. CLI 는 대화를 기억하지 않으니 파일읽기 결과의 `그림` id 를 쓴다). 사진 파일은 사진 속 글자를 자료로 읽지 않는다. 문서에는 `"그림":"img-…"` 만 쓰고 파일·쪽·자를곳 좌표는 쓰지 않는다(경로·경계는 시스템이 푼다). 로고·스캔 쪽·선 도식은 쓰지 않는다. 한글·워드 문서(HWP·HWPX·DOCX) 속 그림은 id 없는 '문서 속 사진' 카드로만 오르고 쓰지 않는다(문서를 PDF로 저장해 함께 올리거나 사진 파일로 올려야 쓴다 — 끝 보고에 알린다. 문서를 풀어 속 원본을 꺼내 올리지 않는다). 그림 자리는 풀버전 절의 `이미지`, 옛 판형 슬라이드 '이미지' 장, 보도자료 끝 `붙임사진`뿐이다(1p·시행문·규정·판형 v2 는 없다). 설계(빌드플랜)에 `그림계획`을 적으면 초안 지시문에 실리고, 빠지면 확인할 것에 오른다.
  - **그림은 세 길 중 앞에서부터**: ① 구조·수치는 도식·차트(SVG) ② 올린 첨부에 맞는 그림이 있으면 목록 id 로 쓴다 ③ 둘 다 아니고 삽화가 꼭 도움이 될 때만 만든다. 새로 만드는 곳은 **옛 판형 슬라이드 '이미지' 장뿐**이다(풀버전·보도자료·1p·시행문·규정·판형 v2 에는 생성 그림을 넣지 않는다 — 새문서가 빼고 확인할 것에 올린다).
  - **만들 수 있는지는 당신의 도구 목록으로 확인한다.** Codex `image_gen` · OpenClaw `image_generate` · Gemini CLI `generate_image`(nanobanana 확장) · Cursor 내장 이미지 생성 · 그 밖의 이미지 생성 MCP 가 있을 때만이다(Claude 자체에는 이미지 생성 기능이 없다). 있으면 그 이름으로 `이미지능력`(imagegen, tool=도구 이름)을 불러 켠다. 켠 것은 **이 대화에서만** 간다(2시간 무활동이면 잊는다) — 새 대화에서는 다시 켜고 사용자에게 다시 묻는다. CLI 는 대화를 기억하지 않으므로 그림 요청이 생길 호출(new·save·build)마다 `"image_tool": "도구 이름"`을 싣는다. 없으면 켜지 않는다 — 그러면 지시문이 생성을 시키지 않는다. 사진이 필요하면 사용자에게 올려 달라고 하거나 그림 없이 쓴다. 환경변수(`IMAGEGEN_HOST`)로는 켜지지 않는다.
  - 만들기 전(설계 승인 때) 사용자에게 한 줄로 묻는다: 몇 장을 어느 도구로 만드는지, 이용 한도를 쓰고 그림 설명이 그 도구의 제공자로 간다는 것. 그다음 새문서·조립 응답의 **`그림대기`**(로그의 '▸ 그림 대기' 블록, `이미지대기`/imagequeue 로도 본다 — id·프롬프트·크기)대로 **한 장씩** 그리고, 그린 파일을 `이미지채움`(imagefill: id · tool · path, 경로가 없으면 content_base64)에 넘긴다. 시스템이 형식·크기를 보고 메타데이터를 벗긴 뒤 파일 안과 화면에 'AI 생성물' 표기를 붙여 넣고, 그 문서만 다시 조립·검사한다. 자산 폴더에 파일을 바로 놓으면 쓰지 않는다(이미지채움으로만 넣는다). 올린 자료·웹·스톡 사진을 넣지 않는다(올린 사진과 같은 그림은 시스템이 거절한다 — 한글·워드 문서 속 사진도 거절 해시로 맞대 거절한다). 편집기를 열기 전에 끝낸다. 넣은 그림은 프롬프트가 같은 동안 다시 조립해도 유지되고, 프롬프트를 바꾸면 새 요청('다시 그려야 함')이 된다.
  - 못 만든 그림은 산출물(PDF·HWPX·PPTX·MD)에서 빈 자리 없이 빠지고 편집기에만 검토 표지로 남는다. **사실을 주장하는 도해·차트·기관 상징, 실제 사람·기관·행사를 사진처럼 만든 그림은 생성 금지**(가드가 거부) — 도식(SVG)·데이터 차트·첨부로 해결한다. 프롬프트에 실명·실제 기관 이름을 쓰지 않고(○○), 그림 속 글자를 시키지 않는다(캡션·라벨은 문서 글자로).
- **폰트**: 결과물은 폰트를 내장해 어느 환경에서든 같게 렌더된다(기본 고딕, 명조·한글 원본은 옵션).
- **검증 원칙**: 조판 판정은 반드시 최종 인쇄물(PDF)에서 확인한다 — 화면과 인쇄는 미세하게 다르다.
- **규칙 개선 피드백**: 사용자의 수정이 규칙 차원의 문제를 드러내면, 동의를 받은 뒤에만(능동 동의·기본 꺼짐) `동의코퍼스`로 남긴다. 원문·개인정보는 저장하지 않고 무엇을 어떻게 바꿨는지만 익명으로 남는다. 동의가 없으면 아무것도 저장하지 않는다.
